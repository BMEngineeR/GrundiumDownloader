GrundiumGrab

A command-line tool that inventories the scans on a Grundium Ocus slide scanner and downloads finished exports as SVS or TIFF files. Run it by hand or on a schedule, on a laptop or a server.

npm install -g github:BMEngineeR/GrundiumDownloader
GrundiumGrab init
GrundiumGrab list
GrundiumGrab download

How it works #

Scans live on the scanner, not in the cloud. The grundium.net portal is a login page plus a relay that forwards commands to the device. A scan reaches you only as an export: the scanner writes an SVS or TIFF file and serves it at a plain HTTPS URL on the device host.

GrundiumGrab has two halves:

  1. Browser half. Headless Chrome logs in to grundium.net, opens the scanner's web UI, and reads the archive listing and the export queue from the app's own network traffic. Nothing about the signed protocol is reimplemented.
  2. HTTP half. Finished exports are downloaded with ordinary HTTP requests. Downloads resume from a .part file, are checked against the server's size, and must start with a TIFF or BigTIFF header before they are moved into the destination folder.

All state is kept in a JSON manifest keyed by the scanner's image UUID. scans.csv is a readable view of that manifest and is rewritten after every refresh.

The tool only reads from the scanner unless you run export or enable autoExport. It never claims the scanner's control lock and never deletes anything on the device.

How export works #

Understanding this explains why the tool has both an export and a download command.

On the scanner

  • A scan is stored on the device as tiles in Grundium's own format, indexed by an image UUID. That is what the archive lists, and it cannot be downloaded as is.
  • Pressing Export in the web UI sends one command to the scanner, DExportStart, with the destination WebDL ("make it available for web download"), the format (SVS or TIFF) and the image UUID. Destination and format come from the export recipe saved on the account.
  • The scanner queues the job and stitches the tiles into a single file. Small slides take under a minute, large ones many minutes. It only works when the scan has a scanned area; overview-only captures have none and are refused with a dialog.
  • While it works, the web UI polls DExportStateGet, which returns the queue length, ongoing jobs with a progress fraction, completed jobs and failed jobs. A completed job carries a plain HTTPS URL on the device host that needs no login.
  • The exported file stays on the scanner's disk until someone deletes it from the Exports menu. Each one is a full copy, which is why free space drops as you export.

What GrundiumGrab does

  1. Logs in and opens the scanner's archive page in headless Chrome, the same page you would use by hand.
  2. Types the scan name into the search box so exactly one card remains.
  3. Clears the selection the web app remembers from earlier sessions by toggling the header checkbox until it reads "0 of N selected". Without this, Export would act on whatever was selected last time.
  4. Ticks the one remaining card and reads the side panel to confirm it shows that scan's name. If not, it stops and records the reason.
  5. Presses Export and watches the network for the DExportStart call. Result code 0 means the export started; the export ID is recorded and the scan becomes exporting. If the "cannot be exported" dialog appears instead, it presses Cancel and marks the scan not_exportable.
  6. With --wait or --download it stays on the page and reads each DExportStateGet reply until the job shows up as completed with its URL. The scan becomes downloadable; with --download the file is fetched over plain HTTP, verified, and the scan becomes downloaded.
  7. Rewrites scans.csv.

Without --wait the tool exits right after step 5 and the scanner keeps working on its own. The next list or download finds the finished export in the completed list and continues from there.

Installation #

Requires Node.js 20 or newer.

npm install -g github:BMEngineeR/GrundiumDownloader

This installs the global GrundiumGrab command (also available as grundium-grab). The package has no install scripts. Chrome for Testing, about 350 MB, is downloaded into ~/.cache/puppeteer on first use or with GrundiumGrab setup.

On Linux servers also install unzip and the Chrome runtime libraries:

sudo apt-get install -y unzip libnss3 libatk-bridge2.0-0 libgbm1 libasound2

For development, clone the repository and run npm install && npm link.

Quick start #

mkdir ~/slides && cd ~/slides
GrundiumGrab init          # asks for your grundium.net email and password
GrundiumGrab login         # confirms the credentials and lists your scanners
GrundiumGrab list          # reads the archive, writes scans.csv
GrundiumGrab export --name <part of a scan name> --download
                           # asks the scanner to export that scan, waits, downloads it
GrundiumGrab download      # later: downloads anything else that has a finished export
GrundiumGrab verify        # checks the files on disk

The export step is the one that makes files: a scan can only be downloaded after the scanner has exported it. Use --limit 3 instead of --name to export the three newest scans. See How export works.

init creates a project folder. Every other command finds the project by walking up from the current directory to the nearest grundium.json, so run them from inside that folder or any subfolder.

Command reference #

GrundiumGrab setup #

Downloads the pinned Chrome for Testing build if it is missing or incomplete and prints the executable path. Every browser command performs the same check on its own, so setup is only for doing it up front, for example when building a server image.

The archive is extracted with the system unzip when one exists. Set PUPPETEER_CACHE_DIR to change where Chrome is stored.

GrundiumGrab init [dir] #

Creates a project in dir (default: the current directory): grundium.json with the settings, the .grundium/ state folder, the download folder, and a .gitignore that keeps secrets and data out of version control. Prompts for the grundium.net email and password unless given as options or environment variables.

-u, --username <email>
grundium.net account email.
-p, --password <pw>
Account password. Prefer the interactive prompt or GRUNDIUM_PASSWORD so it does not land in shell history.
--device <name>
Substring of the scanner name or UUID when the account can see several scanners.
--dest <dir>
Download folder, relative to the project. Default downloads.
--format SVS|TIFF
Export format requested by export. Default SVS.

Running init again in an existing project updates the settings and keeps stored credentials unless new ones are given.

GrundiumGrab config #

GrundiumGrab config show                    # print settings (credentials shown as stored/none)
GrundiumGrab config set intervalMinutes 30  # change one key in grundium.json
GrundiumGrab config set autoExport true
GrundiumGrab config credentials             # replace the stored email and password

Values given to set are parsed: true/false become booleans and plain numbers become numbers. See Configuration file for the keys.

GrundiumGrab login #

Logs in once, prints the account, where the credentials came from (key file, passphrase or environment), and the scanners the account can see. Exits without touching the scanner. Use it to check credentials and to find the value for the device setting.

GrundiumGrab list #

Refreshes the inventory from the scanner, merges it into the manifest, rewrites scans.csv and prints the result. Read-only on the scanner.

--cached
Do not contact the scanner; print from the manifest.
-f, --format table|csv|json
Output format. Default table.
-s, --status <status>
Only rows with this status.
-n, --name <substring>
Only rows whose name contains this text, case-insensitive.
--selected
Only rows marked with x in the select column.
GrundiumGrab list                           # newest first
GrundiumGrab list --status downloadable     # ready to download
GrundiumGrab list --name GBM -f csv > gbm.csv
GrundiumGrab list --cached -f json

The refresh also logs the export queue (queued, ongoing, completed, failed), the scanner's free space and its current state (Idle or Scanning).

GrundiumGrab download #

Downloads every scan with status downloadable and retries those marked failed. Refreshes the inventory first unless --cached is given. Read-only on the scanner.

--cached
Skip the refresh and use the manifest as it is.
-s, --selected
Only rows marked with x in the select column of scans.csv.
-n, --name <substring>
Only scans whose name contains this text.
--uuid <uuid>
Exactly one scan by image UUID.
-l, --limit <n>
Stop after this many files.

For each file the tool sends a HEAD request to learn the size, streams the body into <name>.svs.part, resumes from that file with a Range request if it already exists, and after the transfer checks that the size matches and that the header is TIFF or BigTIFF. Only then is the file renamed into the destination folder and the manifest updated with the path, size and timestamps. A file that is already present and valid is adopted without downloading.

Downloads go through the scanner's cloud relay unless the machine can reach the scanner directly. Expect roughly 10 MB/s via the relay; a 1 GB slide takes about two minutes.

GrundiumGrab verify #

Checks every downloaded entry against the disk without contacting the scanner. Files that are missing go back to downloadable (or not_exported when the export URL is gone); files that fail the size or header check go to failed; the rest get a fresh verified_at. Prints the ok, broken and missing files and a count of what is still not downloaded, by status.

--deep
Also run tiffinfo on each file when libtiff is installed.

GrundiumGrab export #

Asks the scanner to export scans that have no export yet, using the export recipe saved on the account (destination WebDL, format SVS or TIFF), then rewrites scans.csv. A scan is stored on the device in its own format; an export is the scanner writing an SVS/TIFF copy, which takes from under a minute for a small slide to many minutes for a large one. Exported scans show as exporting and become downloadable once the scanner finishes.

-n, --name <substring>
Only scans whose name contains this text.
--uuid <uuid>
Exactly one scan.
-s, --selected
Batch mode: every scan marked with x in the select column of scans.csv. See Batch export from scans.csv.
-l, --limit <n>
Maximum number of exports to start. Default 1, or all marked rows with --selected.
--dry-run
Only print what would be exported.
-w, --wait
Stay connected until the started exports finish and mark them downloadable.
-d, --download
Implies --wait. Download the exported files as soon as they are ready and mark them downloaded. Only the scans this command exported are downloaded; use download for everything else.
GrundiumGrab export --dry-run --limit 5          # preview
GrundiumGrab export --name N14-JM --limit 1      # start one export, come back later with "download"
GrundiumGrab export --limit 3 --download         # export, wait, download, all in one go
GrundiumGrab export --selected --download        # every row marked with x in scans.csv

Batch export from scans.csv #

  1. Run GrundiumGrab list so scans.csv is current.
  2. Open scans.csv in Excel, Numbers, LibreOffice or a text editor. Put an x (or yes, 1) in the select column for every scan you want. Save as CSV. Byte-order marks, CRLF line endings and quoted fields from spreadsheets are fine.
  3. Run GrundiumGrab export --selected --download. It reads the marks back, exports every marked scan that has no export yet, waits for them, downloads them and rewrites the file. Marked scans that are already downloadable are reported; fetch them with GrundiumGrab download --selected.

Marks are matched by the uuid column, so reformatting of dates or sizes by the spreadsheet does not matter. They survive every refresh and are cleared automatically when the scan reaches downloaded. GrundiumGrab list --cached --selected shows what is currently marked.

For each scan the tool searches the archive by name, clears any selection the web app remembered from earlier sessions, ticks the one matching card, confirms that the side panel shows that scan, and only then presses Export. If any of these checks fails it refuses to press the button and records the reason in last_error.

Each export is a full copy of the slide on the scanner's disk. Keep --limit small and clear finished exports on the device from time to time.
Overview-only captures, typically named like 20260610 Scanned Image 2627 and around 90 MB, have no scanned area. The scanner refuses to export them; the tool cancels the dialog and marks them not_exportable so they are not retried.

GrundiumGrab run #

The scheduled loop. Each cycle: refresh the inventory, trigger exports if autoExport is on (at most maxExportsPerCycle in flight), download everything downloadable, record the results.

-i, --interval <minutes>
Minutes between cycles, overriding intervalMinutes. 0 runs one cycle and exits, which is the form to use from cron.
GrundiumGrab run                 # forever, interval from grundium.json
GrundiumGrab run --interval 0    # one cycle

A lock file at .grundium/run.lock prevents two instances from overlapping; a second instance exits with code 2. Logs are one JSON object per line on stdout, errors on stderr.

GrundiumGrab status #

Prints the manifest summary: total scans and a count per status, plus when the inventory was last refreshed. No scanner contact.

Scan statuses #

StatusMeaningWhat to do
not_exportedOn the scanner, no export exists yet.Run export or enable autoExport.
exportingExport queued or running on the scanner.Wait; the next refresh will pick it up.
downloadableA finished export URL exists.download fetches it.
downloadedFile on disk passed verification.Nothing.
failedLast download or verification failed; see last_error.Retried on the next download.
not_exportableThe scanner refused to export it (no scanned area).Nothing; it is skipped from now on.
goneNo longer listed on the scanner.Kept for history only.

The file is sorted newest first and rewritten after every refresh, download and verify. It contains user emails, so it is listed in .gitignore.

Credentials and security #

The password is stored in .grundium/credentials.enc, encrypted with AES-256-GCM.

  • Default: the key is a random 32-byte file at .grundium/key with mode 600.
  • Servers: set GRUNDIUM_PASSPHRASE before init. The key is derived from the passphrase with scrypt and no key file is written. Export the same variable in the service unit or cron environment.
  • Override: GRUNDIUM_USERNAME and GRUNDIUM_PASSWORD in the environment take precedence over the stored file.

This protects against accidental commits, backups and casual reading. It does not protect against someone who can already run code as your user. Never commit .grundium/.

Running on a schedule #

cron

*/15 * * * * cd /path/to/project && /usr/local/bin/GrundiumGrab run --interval 0 >> grab.log 2>&1

systemd

[Unit]
Description=GrundiumGrab
After=network-online.target

[Service]
WorkingDirectory=/path/to/project
Environment=GRUNDIUM_PASSPHRASE=change-me
ExecStart=/usr/bin/GrundiumGrab run
Restart=always
User=slides

[Install]
WantedBy=multi-user.target

launchd (macOS)

Create a LaunchAgent plist with ProgramArguments of GrundiumGrab run and WorkingDirectory set to the project. Keep the Mac awake, or wrap the command in caffeinate.

Troubleshooting #

Chrome fails to launch with dlopen ... Framework. The browser bundle is incomplete. Delete ~/.cache/puppeteer/chrome and run GrundiumGrab setup. If it happens again, install unzip; the tool uses it to extract the bundle correctly.

Login failed: Function returned non-zero. Wrong email or password. Run GrundiumGrab config credentials.

No device matches. Check the names printed by GrundiumGrab login and set config set device <substring>.

another instance holds the lock. A previous run is still going, or it crashed. If no process is running, delete .grundium/run.lock.

Something else looks wrong. Run with GRUNDIUM_HEADLESS=false to watch the browser, and look in .grundium/captures/ for the recorded RPC calls and screenshots of each session.

Limitations #

  • Tested against a live scanner: init, login, list, download (including abort, resume, verification and adoption of existing files), verify, export with and without --download, the overview-only refusal path, and the one-command install.
  • Not yet exercised on a live device: run with autoExport enabled (it uses the same export code as export).
  • The tool relies on the grundium.net web app's internal protocol, which is not a published API. A portal update can break the listing or export steps; the captures folder is the first place to look.
  • Exports occupy disk on the scanner. Keep maxExportsPerCycle small and clean up finished exports on the device from time to time.
